# Evacuation-sim

Приложение на Java для исследования эвакуации из здания. Версия **0.2.0** связывает SVG-план, явное количество людей, поиск маршрутов, очереди на проходах и браузерный интерфейс в одном запускаемом приложении.

Сейчас реализован расчёт одного этажа: время движения между помещениями, пропускная способность дверей и выходов, выбор пути с учётом очередей и закрытие отдельных проходов. На плане отображаются использованные маршруты; в таблицах — время выхода и ожидание на проходах.

## Запуск

Нужны **JDK 25** и **Maven 3.9.9+**. Команды выполняются из корня репозитория:

```bash
mvn -B -f evac_sim/pom.xml clean verify
java -Djava.awt.headless=true -jar evac_sim/target/evac-sim-0.2.0.jar --serve 8080
```

Откройте [http://127.0.0.1:8080/](http://127.0.0.1:8080/). Сервер слушает только локальный адрес. JAR содержит зависимости и встроенные SVG-примеры, отдельный веб-сервер не нужен.

1. Откройте встроенный пример или загрузите свой [размеченный SVG](evac_sim/format_spec.md).
2. Укажите число людей в каждом помещении. Для своего файла начальные значения равны нулю; кнопка «По вместимости комнат» задаёт отдельный демонстрационный сценарий.
3. При необходимости отметьте закрытые двери/выходы и задайте скорость ходьбы.
4. Выполните расчёт и сравните время, маршруты и очереди после изменения сценария.

Для встроенного офисного примера полная загрузка комнат — **66 человек**. Закрытие обоих выходов должно дать 66 человек без пути наружу.

Сохранён консольный просмотр плана и исходного графа:

```bash
java -jar evac_sim/target/evac-sim-0.2.0.jar examples/example.svg
java -jar evac_sim/target/evac-sim-0.2.0.jar /path/to/floor.svg
```

## Связанные библиотеки

| Библиотека | Версия | Работа в приложении |
|---|---|---|
| Apache Batik | 1.20 | SVG path, кривые, дуги, points и вложенные SVG transform |
| JGraphT | 1.5.3 | Дейкстра на графе с параллельными проходами и весами, учитывающими очереди |
| Jackson | 2.22.4 | Типизированный JSON между браузером и расчётом |
| JUnit Jupiter | 5.10.2 | Проверки геометрии, аналитических очередей, блокировок и HTTP-интеграции |

Веб-адаптер использует HTTP-сервер JDK. Maven проверяет совместимость Java и сходимость зависимостей; Shade собирает исполняемый JAR вместе с библиотеками и лицензионными уведомлениями. [Выбор библиотек и альтернативы](docs/LIBRARIES.md).

## Модель и её границы

- `data-capacity` — вместимость, `occupancy` — фактическое число людей в выбранном сценарии. Это разные величины.
- Время движения оценивается по расстояниям между центрами габаритов помещений и проходами с учётом `data-scale`. Пропускная способность задаётся в чел/с; один человек занимает проход на `1 / throughput` секунд. Дверь имеет общий ресурс для двух направлений.
- Поиск пересчитывается при достижении очередного помещения с учётом известных очередей и людей, направляющихся к проходу. Это эвристика распределения, **глобальный минимум времени не гарантируется**.
- Вместимость проверяется для начального размещения. Заполнение коридоров, обратное распространение заторов, индивидуальная физика толпы и обход внутренних препятствий пока не рассчитываются. Линии маршрутов показывают связи, а не точные безопасные траектории внутри комнат.
- Лестницы читаются парсером, но исключены из расчёта одного этажа с явным предупреждением. Многоэтажное движение, расписание, пожар и БПЛА входят в [план следующих этапов](docs/ROADMAP.md).

Предыдущие `login.html`, `admin.html` и `viewer.html` сохранены как отдельная браузерная демонстрация сеточной модели с localStorage. Ссылка есть в интерфейсе. Её демонстрационный пароль `admin` не является серверной авторизацией; её отметки и результаты не передаются новому расчётному сервису.

## API и проверки

`GET /api/health` возвращает состояние и версию. `POST /api/analyze` принимает JSON:

```json
{
  "svg": "<svg xmlns=\"http://www.w3.org/2000/svg\" ...>...</svg>",
  "occupancy": {"R101": 8, "R102": 4},
  "blockedConnections": ["E_left"],
  "walkingSpeedMps": 1.3
}
```

`svg` обязателен. Отсутствующие помещения в `occupancy` считаются пустыми; `null` или пустой объект тоже означают нулевую загрузку. Скорость по умолчанию — 1.3 м/с. Ответ содержит `nodes`, `connections`, `routes`, `bottlenecks`, числа эвакуированных/оставшихся без пути, время последнего успешного выхода и предупреждения. Ошибки имеют вид `{"error":"..."}`.

Ограничения начальной версии: запрос до 2 МиБ, до 10 000 человек, 2 000 узлов, 5 000 дверей/выходов, произведение числа людей и узлов до 2 000 000. Дополнительно ограничена оценка вычислительной работы: `люди × узлы × (узлы + 2 × связи) ≤ 50 000 000`. Проверяются уникальные идентификаторы, ссылки, конечные положительные параметры, вместимость и целые количества людей. DTD и внешние XML-сущности запрещены.

```bash
mvn -B -f evac_sim/pom.xml test
```

GitHub Actions выполняет `clean verify`, проверяет запуск JAR и сохраняет готовый JAR в артефактах сборки.

Дополнительная браузерная проверка при установленном Node.js, пакете `playwright` и Chromium:

```bash
# Приложение должно быть запущено на порту 8080.
node scripts/browser-smoke.cjs
```

Другой адрес задаётся переменной `EVAC_URL`, путь к браузеру — `CHROMIUM_PATH`.
