# Evacuation-sim

Приложение для моделирования эвакуации из SVG-планов здания. Версия **0.3.0** объединяет редактор зданий и сценариев, SQLite, серверную авторизацию и Java-расчёт маршрутов, очередей и межэтажного движения. Браузер воспроизводит журнал готового расчёта; движение и очереди рассчитываются одним Java-движком.

## Сборка и запуск

Нужны **JDK 25**, **Maven 3.9.9+**, **Node.js 22** и **npm** в `PATH`. Из корня репозитория:

```bash
mvn -B clean verify
java -Djava.awt.headless=true -jar server/target/evacuation-sim-0.3.0.jar
```

Maven собирает `evac_sim` и `server`, выполняет `npm ci` и `npm run build` в `web`, затем включает `web/dist` в серверный JAR. Для запуска готового JAR Node.js и Maven не нужны.

Откройте [http://127.0.0.1:8080/](http://127.0.0.1:8080/). Зарегистрируйте учётную запись и войдите. Общего пароля `admin`/`admin` нет. SQLite создаётся в `./data/evac.db`, миграции применяются при запуске.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `127.0.0.1` | Адрес сервера |
| `PORT` | `8080` | Порт |
| `DB_PATH` | `./data/evac.db` | Файл SQLite |
| `SESSION_TTL_HOURS` | `168` | Срок сессии, от 1 до 720 часов |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | Не заданы | Начальная учётная запись; задаются вместе и используются только при пустой таблице пользователей |

Имя переменной `ADMIN_USERNAME` сохранено для совместимости. Разделения пользователей на роли в этой версии нет; здания принадлежат создавшему их пользователю.

## Контейнер

Сначала соберите и проверьте JAR командой `mvn -B clean verify`, затем выполните `docker compose up --build`. Образ включает готовый JAR и Java 25; SQLite хранится в отдельном томе. Интерфейс доступен на [http://127.0.0.1:8080/](http://127.0.0.1:8080/).

## Первый расчёт

1. Создайте здание и добавьте SVG-планы с уникальными уровнями этажей.
2. Создайте сценарий. Выберите один формат планов для всего здания: размеченные помещения либо обычные планы с метками.
3. Задайте скорость и масштаб. На обычных планах расставьте метки «Люди», «Выход» и при необходимости «Лестница», укажите ширины выходов/лестниц и сохраните сценарий.
4. Перейдите к расчёту. Для размеченных SVG укажите число людей по помещениям. Для обычных планов общее число людей распределяется между метками «Люди»; свяжите лестницы верхнего и нижнего этажей по их номерам.
5. При необходимости закройте отдельные проходы и выполните расчёт. Сравните две стратегии, использованные маршруты, время выхода и ожидание на проходах.
6. Воспроизведите движение, поставьте его на паузу или выберите момент на временной шкале. Сохранённый расчёт можно открыть повторно даже после изменения планов здания.

### Два формата планов

| | Размеченный SVG (`semantic`) | Обычный SVG с метками (`raster`) |
|---|---|---|
| Топология | `data-type`, `data-id`, `data-connects` в SVG | Проходимая растровая сетка и метки сценария |
| Масштаб | `data-scale`: **метры на единицу SVG** | Параметр сценария `scale`: **единицы SVG в одном метре** |
| Люди | Фактическая заполненность каждого помещения | Общее число людей, распределённое поровну между метками «Люди» |
| Лестницы | `data-connects="C1@1,C1@2"`, `up/down/both` | Явная пара `fromMarkId → toMarkId`, направленная на более низкий уровень |
| Геометрия пути | Отрезки через центры помещений и проходы | Пути по сетке вокруг тёмных линий плана |

Например, при 50 единицах SVG в метре в сценарии задают `scale=50`, а в размеченном SVG — `data-scale="0.02"`. Если `data-scale` отсутствует, сервер использует `1 / scale`. Уровень из карточки этажа определяет его положение в здании.

Идентификаторы размеченных помещений в настройках имеют вид `floorId/roomId`, например `12/R101`: одинаковые локальные `data-id` на разных этажах не конфликтуют. Вместимость `data-capacity` ограничивает начальное размещение и не подменяет фактическую заполненность.

У обычных планов лестницы могут находиться в разных координатах на этажах. Явно выберите обе метки на экране расчёта. Для старых сценариев без явных пар сохранён поиск одинаковых координат на соседних уровнях с предупреждением о необходимости проверить связи. Смешивать два формата этажей внутри одного расчёта нельзя.

Подробности разметки: [формат SVG](evac_sim/format_spec.md). Источники объединения и устройство приложения: [INTEGRATION.md](docs/INTEGRATION.md).

## Расчёт и сохранение результатов

Движок сравнивает кратчайшие пути (`SHORTEST_PATH`) с маршрутизацией, учитывающей очереди (`QUEUE_AWARE`). Сначала выбирается результат с большим числом вышедших людей, при равенстве — с меньшим временем последнего выхода. Обе оценки показаны в интерфейсе. Такое сравнение не доказывает глобально минимальное время эвакуации.

Дверь, выход или лестница — общий ресурс с пропускной способностью в чел/с. Один человек занимает ресурс на `1 / throughput` секунд; время движения по лестнице задаётся отдельно. Закрытые проходы исключаются до начала расчёта. Невозможность выйти отображается отдельно и не считается успешным освобождением здания.

В SQLite сохраняются настройки сценария и до **20 последних расчётов на сценарий**. Каждый расчёт содержит снимок сети, этажей, заполненности, параметров и блокировок, результат с временными сегментами каждого человека, версию движка и SHA-256 входа. Старое воспроизведение использует сохранённый план и времена, а не текущее состояние редактора. Автоматического повторного запуска произвольной старой версии движка пока нет.

Пожар в расчёт v0.3.0 не входит. Для сценария с ранее сохранённым очагом откройте редактор, нажмите «Убрать очаг» и сохраните сценарий. Физическая плотность толпы, заполнение коридоров с распространением заторов назад, индивидуальное поведение и калибровка на реальной эвакуации остаются следующими этапами.

## API

Основные запросы используют cookie `SESSION` после входа. Здания, этажи, сценарии и расчёты доступны их владельцу.

| Метод и путь | Назначение |
|---|---|
| `POST /api/auth/register`, `POST /api/auth/login` | Регистрация и вход |
| `GET /api/buildings` | Здания текущего пользователя |
| `GET /api/buildings/{bid}/scenarios/{sid}/topology` | Сеть, начальная заполненность и предупреждения |
| `GET`, `PUT /api/buildings/{bid}/scenarios/{sid}/simulation-settings` | Заполненность, блокировки, пары растровых лестниц |
| `POST /api/buildings/{bid}/scenarios/{sid}/simulate` | Расчёт и сохранение результата |
| `GET /api/buildings/{bid}/scenarios/{sid}/runs` | История расчётов |
| `GET /api/buildings/{bid}/scenarios/{sid}/runs/{rid}` | Сохранённый расчёт и планы для воспроизведения |
| `GET /api/health`, `GET /api/health/db` | Состояние приложения и базы |

Пример настроек для размеченного этажа с `id=12`:

```json
{
  "occupancy": {"12/R101": 8, "12/R102": 4},
  "blockedConnections": ["12/E_left"],
  "stairLinks": []
}
```

## Разработка и проверка

Общая сборка и Java-проверки: `mvn -B clean verify` из корня. Отдельные проверки воспроизведения: `npm --prefix web test`. Браузерный прогон и результаты проверки выпуска описаны в [RELEASE_v0.3.0.md](docs/RELEASE_v0.3.0.md).

Для разработки интерфейса запустите сервер, затем `npm --prefix web run dev`. Vite работает на [http://localhost:5173/](http://localhost:5173/) и передаёт `/api` серверу на порту 8080.

| Каталог | Содержание |
|---|---|
| `evac_sim/` | Java-модели, SVG-парсер, единый событийный движок, проверки ядра |
| `server/` | Javalin API, авторизация, SQLite/Flyway, адаптеры двух форматов планов |
| `web/` | TypeScript/Vite, редактор, результаты и воспроизведение |
| `docs/` | Состояние, план развития, происхождение объединения и выпуски |

Исторический адаптер ядра `/api/analyze` и прежние HTML-страницы сохранены в модуле `evac_sim` для совместимости; основной серверный JAR использует интерфейс из `web/dist` и API сценариев.
