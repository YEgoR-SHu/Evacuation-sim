# v0.3.0 — единое приложение эвакуации

Исходные состояния объединения: ядро `22b6a1bef66ebcbf93751c586099aeb0cde85da6` и платформа `a06a6613fcec2c38281baef512099925de80c730`. Источники и авторство: [INTEGRATION.md](INTEGRATION.md).

## Состав

- Корневая Maven-сборка Java 25: ядро `evac_sim`, Javalin-сервер `server`, TypeScript/Vite-интерфейс из `web/dist` в одном серверном JAR.
- Серверные учётные записи и сессии, доступ владельца к зданиям, SQLite/Flyway для этажей, сценариев, меток, настроек и результатов.
- Два адаптера планов к одному Java-движку: семантическая разметка и обычный SVG с метками/растровыми путями.
- Многоэтажные пути: `data-connects` и направления семантических лестниц либо явные пары меток на разных этажах.
- Сравнение кратчайших путей и маршрутизации с очередями; отдельно показаны вышедшие люди, недостижимые, время и ожидание.
- Сохранение 20 последних запусков сценария со снимком входа, планов, версией и SHA-256; воспроизведение готового журнала в браузере с паузой и перемоткой.

Физическая плотность толпы, обратное распространение заторов, пожар/дым, БПЛА и доказанная глобальная оптимизация в выпуск не входят. Сценарий с сохранённым очагом перед расчётом нужно очистить от него и сохранить. Полные границы: [PROJECT_STATUS.md](PROJECT_STATUS.md).

## Сборка и проверка

Требуются JDK 25, Maven 3.9.9+, Node.js 22 и npm. Из корня:

```bash
mvn -B clean verify
npm --prefix web test
java -Djava.awt.headless=true -jar server/target/evacuation-sim-0.3.0.jar
```

Общая сборка выполняет установку frontend-зависимостей и `tsc --noEmit && vite build`. Проверки Java включают ядро и сервер. Отдельная команда npm проверяет функции воспроизведения.

При запущенном приложении и установленном Chromium дополнительный сквозной прогон выполняется командой `node scripts/browser-smoke.cjs`. Он использует Playwright из `web`; другой адрес сервера задаётся через `EVAC_URL`, путь к браузеру — `CHROMIUM_PATH`. Свидетельства сохраняются в `test-results/`.

В итоговом браузерном прогоне проверяются регистрация/вход, создание здания, оба формата планов, этажи с лестницами в разных координатах, заполненность, закрытые выходы, сохранённые результаты после редактирования плана, пауза и перемотка. Итоговые числа людей должны совпадать с журналом Java-движка; недостижимые люди не должны исчезать как успешно эвакуированные.

**Проверено 9 ноября 2026 года:** общая сборка `clean verify` прошла, **119 Java-тестов** (95 ядра и 24 сервера), **4 проверки воспроизведения** и расширенный браузерный тест SVG/CSS прошли без ошибок. Сквозной прогон готового JAR проверил 8 групп сценариев: регистрацию и создание здания, расчёт 66 человек по размеченному плану, сохранение/перемотку, блокировку выходов с сохранением 66 недостижимых людей, экран 390 px, сброс устаревших настроек после правки плана, два этажа с явными связями лестниц, очистку SVG и ограничение доступа. В браузере ошибок JavaScript не было. Тот же сквозной прогон прошёл и в собранном Docker-образе под непривилегированным пользователем; результаты обоих запусков совпали.

Контрольный офис: 66 человек при двух выходах — **22,62084 с**; при закрытии обоих — 66 человек без пути. Двухэтажный план с метками — все 8 человек вышли за **20,69231 с**. Это воспроизводимые результаты данной модели, а не измерения эвакуации реального здания. Серверный JAR содержит 85 отдельных лицензионных файлов зависимостей; тестовые классы в него не включены.

## Контейнерная поставка

После успешной Maven-сборки выполните `docker compose up --build`. Dockerfile упаковывает уже проверенный `server/target/evacuation-sim-0.3.0.jar` вместе с Java 25 и запускает его от отдельного пользователя. В образ не копируются Maven, npm, исходники или локальная база; данные находятся в томе `/app/data`.

Серверный стек обновлён до Javalin 7.2.4 / Jetty 12.1.14, Logback 1.5.38, SQLite JDBC 3.54.1.0. [Проверка координат Java-зависимостей в OSV](DEPENDENCY_CHECK_v0.3.0.json) зафиксирована отдельно; она не заменяет проверку самого приложения.

## Обновление и откат

До запуска на существующей базе сохраните её резервную копию. Автоматической миграции браузерного `localStorage` v0.2.0 в SQLite нет. При первом запуске без переменных начальной учётной записи зарегистрируйте пользователя через интерфейс; пароль `admin` по умолчанию не создаётся.

Объединение предназначено для отдельного коммита/PR; публикация ветки не перезаписывает `main`. После проверки конкретного коммита можно отменить его отдельным обратным коммитом:

```bash
git show --stat <integration-commit>
git revert <integration-commit>
```

Заполнитель нужно заменить проверенным SHA интеграционного коммита. Для merge-коммита отдельно проверяется родитель. Возврат исходников не отменяет миграции SQLite: при возврате к старой схеме восстановите соответствующую резервную копию после остановки сервера. Документ v0.2.0 сохраняет команды и результаты предыдущей версии как историю.
