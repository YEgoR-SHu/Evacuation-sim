# Объединение в v0.3.0

## Происхождение кода

По запросу пользователя в Evacuation-sim объединены его расчётное ядро и работа товарища по серверной оболочке. Исходные состояния:

| Источник | Зафиксированный коммит | Сохранённые части |
|---|---|---|
| [YEgoR-SHu/Evacuation-sim](https://github.com/YEgoR-SHu/Evacuation-sim) | [`22b6a1bef66ebcbf93751c586099aeb0cde85da6`](https://github.com/YEgoR-SHu/Evacuation-sim/commit/22b6a1bef66ebcbf93751c586099aeb0cde85da6) | Java-модели, SVG-парсер Batik, маршрутизация JGraphT, событийные очереди, примеры и проверки v0.2.0 |
| [ArteMyasnik/evac_sim](https://github.com/ArteMyasnik/evac_sim) | [`a06a6613fcec2c38281baef512099925de80c730`](https://github.com/ArteMyasnik/evac_sim/commit/a06a6613fcec2c38281baef512099925de80c730) | Платформа Артёма: Javalin, SQLite, авторизация, здания/этажи/сценарии/метки, TypeScript/Vite |

Во втором репозитории исходники приложения находились в каталоге `evac-sim/`; его `server/`, `web/` и родительский POM адаптированы к корню общего проекта. Имена Java-пакетов `com.artemyasnik` и `com.artemyasnik.evac.server` сохранены. Эта запись сохраняет происхождение работы Артёма и не приписывает весь объединённый код одному участнику.

Новая лицензия на собственный код этим объединением не назначается. Авторство, имеющиеся уведомления и условия сторонних библиотек сохраняются; настоящий документ не является отдельным лицензионным разрешением. Состав зависимостей описан в [LIBRARIES.md](LIBRARIES.md), исторические уведомления ядра — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Единый путь данных

```text
web (TypeScript/Vite)
  → Javalin: авторизация, здания, этажи, сценарии, настройки
  → SemanticNetworkBuilder или RasterNetworkBuilder
  → EvacuationNetwork
  → NetworkSimulationService
  → NetworkResult + входной снимок → SQLite
  → web: результаты и воспроизведение временных сегментов
```

`evac_sim` остаётся Java-библиотекой ядра. `server` зависит от неё и содержит хранение, HTTP API и адаптеры геометрии. `web` содержит редактор и отображение. Корневая команда `mvn -B clean verify` строит оба Maven-модуля и интерфейс; `web/dist` попадает в серверный JAR как `/static`.

Исторический `SimulationService` сохранён как адаптер одноэтажного API к общему движку. Старый `--serve` и демонстрационные страницы ядра не являются основным интерфейсом версии 0.3.0. Основная точка запуска — `com.artemyasnik.evac.server.ServerApp` в `server/target/evacuation-sim-0.3.0.jar`.

## Форматы и единицы

- Семантический SVG: комнаты/коридоры и связи берутся из `data-*`, `data-scale` — **метры на единицу SVG**. Идентификаторы сети содержат `floorId/roomId`. Уровень берётся из карточки этажа, а лестничные ссылки `baseId@floor` ссылаются на эти уровни.
- Обычный SVG: Batik растеризует план, тёмные пиксели становятся препятствиями; пути между метками обходят их по сетке. Параметр `scale` — **единицы SVG в метре**. При отсутствии `data-scale` в семантическом плане его значение получается как `1 / scale`.
- Для обычного SVG явные связи `stairLinks` содержат `fromMarkId` и `toMarkId`. Метки должны быть лестницами, а целевой уровень — ниже исходного. Координаты не обязаны совпадать. При отсутствии явных связей действует прежнее соглашение одинаковых координат на соседних этажах с предупреждением.
- Для семантических лестниц используются `data-connects`, `data-direction` и необязательное `data-travel-time-seconds`. Дополнительные пары растровых меток для них не принимаются.
- `occupancy` — число людей, а `capacity` — предел начального размещения. В семантическом формате пустая заполненность означает ноль. На обычном плане общее число людей по умолчанию распределяется между метками «Люди».

В одном здании выбирается один формат этажей. Произвольная растровая картинка не получает семантические комнаты автоматически.

## Результат, снимок и повторное воспроизведение

Общий движок сравнивает кратчайшие пути и маршрутизацию с учётом очередей. Выбирается вариант с большим числом эвакуированных; при равенстве — с меньшим временем последнего успешного выхода. Глобальная оптимальность не заявляется.

`NetworkResult.people` содержит статусы людей и временные сегменты `move`, `wait`, `passage`, `stairs`, `evacuated`, `unreachable`. Браузер показывает положение по этим сегментам и не выполняет второй расчёт движения. Если часть людей не имеет пути, результат не объявляется полной эвакуацией.

`simulation_settings` хранит заполненность, блокировки и пары лестниц. `simulation_runs` хранит входной снимок сети/этажей/параметров/настроек и ответ с журналом движения, версией `engineVersion` и `inputSha256`. После сохранения остаются 20 последних запусков данного сценария. Открытие результата использует его сохранённые этажи, поэтому последующее редактирование здания не сдвигает старые траектории. SHA-256 относится к сохранённому входному снимку; он не является доказательством физической точности модели.

## Границы интеграции

Объединение реализует базовую эвакуацию. Расчёт сценария с очагом пожара отклоняется; в редакторе можно убрать ранее сохранённый очаг. Нет калиброванной модели огня/дыма, плотности толпы, заполнения коридоров и распространения затора назад. Семантические пути внутри помещений пока приближены. Дальнейшие критерии — [ROADMAP.md](ROADMAP.md).

## Выпуск и откат

Интеграция подготавливается отдельной веткой и одним коммитом/PR для обзора. Создание этой ветки или PR само по себе не изменяет `main`. Зафиксированные исходные SHA выше позволяют сравнить результат с обоими источниками.

Для отката объединения в общей ветке применяется `git revert` к конкретному коммиту интеграции после проверки его состава. Если PR объединён merge-коммитом, выбор родителя для отката проверяется отдельно. Историю не переписывают, а поздние изменения предварительно учитывают.

SQLite перед обновлением следует сохранить вместе с файлами WAL/SHM либо штатной резервной копией после остановки приложения. Откат исходников не откатывает миграции базы; для возврата на старую серверную схему используют соответствующую резервную копию. Точные команды и результаты проверки выпуска приведены в [RELEASE_v0.3.0.md](RELEASE_v0.3.0.md).
