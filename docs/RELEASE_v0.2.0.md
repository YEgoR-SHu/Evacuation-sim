# v0.2.0 — связный начальный расчёт эвакуации

Базовая версия до обновления: `e0e90dae627b6f87bd1701eb56861761f13ca95a`.

## Состав версии

- Batik 1.20 для SVG-геометрии и преобразований вместо неполного разбора `path`.
- JGraphT 1.5.3 для маршрутов с альтернативными проходами и блокировками.
- Событийный расчёт времени движения и очередей по `data-throughput` с явной фактической заполненностью помещений.
- Jackson 2.22.4 и HTTP API, соединяющие Java-расчёт с браузерным интерфейсом.
- Одна Maven-сборка, исполняемый JAR с зависимостями, проверки и CI.
- Актуальное описание состояния проекта, выбранных библиотек и задач до готового продукта.

Сценарии пожара/БПЛА, физическая плотность толпы, многоэтажная эвакуация и доказанная глобальная оптимизация в эту версию не включены. Подробные границы модели: [PROJECT_STATUS.md](PROJECT_STATUS.md).

## Сборка

Требуются JDK 25 и Maven 3.9.9+.

```bash
mvn -B -f evac_sim/pom.xml clean verify
```

Запуск локального интерфейса и API:

```bash
java -jar evac_sim/target/evac-sim-0.2.0.jar --serve 8080
```

Откройте `http://127.0.0.1:8080/`. После запуска следует проверить загрузку примера, явное заполнение комнат, расчёт с открытыми выходами и повтор с одним заблокированным выходом. Количество людей, использованные пути и время должны меняться согласованно; при недостижимом выходе интерфейс должен сообщить об этом. Демонстрационный сценарий приведён в корневом [README](../README.md).

## Проверка версии

На итоговой сборке прошли **87 Java-тестов** и **6 браузерных сценариев**. Проверены все девять SVG-примеров, аналитические очереди, дробная пропускная способность, параллельные выходы, недостижимость, входные ошибки и полный HTTP-конвейер.

В офисном примере с 66 людьми и скоростью 1.3 м/с получено 22.6 с при двух выходах и 34.8 с при одном. При закрытии обоих выходов 66 человек отмечены как не имеющие пути. Это результаты начальной расчётной модели, а не измерения реальной эвакуации. В браузере также проверены собственный SVG, ограничения вместимости, очистка активного SVG-содержимого и ширина экрана 390 px.

## Откат одного обновления

Все изменения версии публикуются одним обычным коммитом. Ветка `release/v0.2.0` указывает на эту версию, а `backup/before-v0.2.0` сохраняет исходное состояние. Для отмены в общей ветке используйте `git revert`: история сохранится, а обратное изменение будет отдельным коммитом.

Чтобы отменить именно эту версию:

```bash
git switch main
git pull --ff-only
git fetch origin
git revert origin/release/v0.2.0
git push origin main
```

Перед отменой проверьте `git show --stat origin/release/v0.2.0`: это должен быть коммит v0.2.0. Если после него появились изменения в тех же файлах, при откате может потребоваться разрешение конфликтов. Не перемещайте ветки сохранённых версий при дальнейшей разработке.

Для отдельной проверки старого состояния без изменения общей ветки:

```bash
git switch --detach e0e90dae627b6f87bd1701eb56861761f13ca95a
```

Перед переключением сохраните текущие незакоммиченные изменения. Запущенный новый сервер после отката нужно остановить; старый исходный код имеет прежние команды запуска и возможности.
