# Состояние проекта

Дата аудита: 23 октября 2026 года. Исходная версия: `e0e90dae627b6f87bd1701eb56861761f13ca95a` (`main`).

## Что было на GitHub до v0.2.0

Проект находился на стадии прототипа отдельных частей. В репозитории были один Maven-модуль на Java 25, модель этажа, DOM-парсер SVG, построение графа, девять SVG-примеров и JUnit-тесты парсера. `Main` выводил разобранный план и рёбра графа в консоль.

Браузерные `admin.html` и `viewer.html` хранили сценарий в `localStorage` и рассчитывали движение на растровой сетке в JavaScript. Они не вызывали Java-парсер или граф. Их лестницы, отметки людей и пожар не были общей моделью с Java-кодом. Пароль `admin` проверялся только в браузере.

Корневой README опережал реализацию: в нём были заявлены JavaFX, Batik, A*, пересчёт при пожаре и тесты классов, которых в исходниках не существовало. Реальный SVG-формат использовал `data-type`, `data-id`, `data-connects`, а не описанные в том README слои и `data-room-a/b`. Рабочая спецификация находилась в `evac_sim/format_spec.md`.

На момент аудита у репозитория была одна ветка `main`; существующих pull request и запусков CI не было. Процент «готовности» не назначается: перечень требований ещё не был превращён в проверяемые критерии приёмки.

## Что связывает v0.2.0

Единый рабочий путь:

1. Пользователь загружает размеченный SVG или выбирает встроенный пример.
2. Java-парсер читает предметную разметку, Batik разбирает SVG-контуры и преобразования, входные значения проходят проверку.
3. Пользователь задаёт фактическое число людей в помещениях и недоступные проходы. Вместимость и число присутствующих — разные параметры.
4. JGraphT ищет маршруты; событийная модель учитывает время движения и обслуживание очередей у проходов с заданной пропускной способностью.
5. Jackson передаёт данные между браузером и Java через `/api/analyze`.
6. Браузер показывает маршруты, количество вышедших и недостижимых людей, расчётное время и нагрузку на проходы.

Java-приложение раздаёт интерфейс и API из одного запуска. Зависимости входят в исполняемый JAR. Вспомогательные демонстрационные страницы сохранены, но основной расчёт выполняется на новой стартовой странице через Java API.

## Границы расчётной модели

- Рассчитывается один размеченный этаж и выходы `OUTSIDE`. Полноценная сборка здания и физическое движение по межэтажным лестницам ещё нужны.
- Проход существует потому, что он явно указан в `data-connects`. Из произвольной картинки или тёмных линий стен топология автоматически не извлекается.
- Время движения оценивается по геометрии узлов и соединителей. Линии маршрута показывают последовательность помещений и проходов; это ещё не точная пешеходная траектория внутри сложного помещения с препятствиями.
- Потоки ограничиваются пропускной способностью проходов. Физическая плотность людей, столкновения и распространение затора обратно по коридору пока не воспроизводятся.
- Заданная скорость и `data-throughput` — исходные параметры сценария. Они требуют измерений и калибровки на реальном объекте.
- Выбор маршрута с учётом текущей очереди — эвристика. Полученное время не доказывает глобальный минимум для всей массы людей.
- Вход — один снимок заполненности. Расписание, время наблюдения, задержка начала движения и изменяющаяся во время расчёта обстановка пока не входят в модель.
- Пожар, БПЛА, убежища с конечной вместимостью и мобильное сопровождение относятся к следующим этапам. Существующая демонстрация огня не подтверждает физическую модель пожара.
- Сервер предназначен для локальной разработки. Серверная авторизация, общее хранилище и эксплуатационное развёртывание ещё не реализованы.
