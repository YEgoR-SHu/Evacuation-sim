# Формат SVG-разметки плана здания для модели эвакуации

Актуально для версии 0.2.0.

План рисуется как обычный SVG (в любом редакторе — Inkscape, Figma с экспортом
в SVG и т.д.), а поверх геометрии добавляются `data-*` атрибуты. Они не влияют
на рендер картинки и легко читаются DOM-парсером.

## Корневой элемент

```xml
<svg data-scale="0.02" data-floor="1"> ... </svg>
```

| Атрибут       | Смысл                                                              |
|---------------|---------------------------------------------------------------------|
| `data-scale`  | метров на 1 единицу координат SVG (масштаб чертежа)                |
| `data-floor`  | номер этажа (для будущей сборки многоэтажного здания)              |

## Узлы: комнаты и коридоры

Любой геометрический тег (`rect`, `polygon`, `path`, `circle`, `ellipse`)
с `data-type="room"` или `data-type="corridor"`.

**Комната** (`data-type="room"`):

| Атрибут          | Обязателен | Смысл                                             |
|-------------------|:---------:|----------------------------------------------------|
| `data-id`         | да        | уникальный id, используется в `data-connects` дверей |
| `data-capacity`   | да        | максимальная вместимость, чел.                     |
| `data-area`       | нет       | площадь, м² (если не задана — считается из bbox × scale²) |
| `data-name`       | нет       | читаемое название                                   |

**Коридор** (`data-type="corridor"`):

| Атрибут          | Обязателен | Смысл                                             |
|-------------------|:---------:|----------------------------------------------------|
| `data-id`         | да        | уникальный id                                       |
| `data-capacity`   | да        | вместимость, чел.                                   |
| `data-width`      | нет       | ширина, м (если не задана — меньшая сторона bbox × scale) |

## Связи: двери, аварийные выходы, лестницы

Любой геометрический тег (обычно `line`, но подойдёт и `rect`/`path`) с
`data-type="door"`, `"exit"` или `"stairs"`. Общие атрибуты:

| Атрибут            | Обязателен | Смысл                                                         |
|----------------------|:---------:|-----------------------------------------------------------------|
| `data-id`           | да        | уникальный id                                                   |
| `data-connects`     | да        | два id через запятую: `"откуда,куда"`                            |
| `data-throughput`   | нет (умолч. 1.0) | пропускная способность, чел/с                             |
| `data-width`        | нет       | ширина проёма/марша, м (если не задана — из bbox × scale)       |

**Дверь** (`data-type="door"`): `data-connects="R1,C1"` — id комнаты и
коридора (или двух комнат/двух коридоров — тоже допустимо).

**Аварийный выход** (`data-type="exit"`): один из id в `data-connects` —
специальное значение `OUTSIDE` (псевдо-узел "улица"), например
`data-connects="C1,OUTSIDE"`.

**Лестница** (`data-type="stairs"`): id узлов задаются в формате
`baseId@floor`, например `data-connects="C1@1,C1@2"` — коридор `C1` этажа 1
соединяется с коридором `C1` этажа 2. Дополнительно:

| Атрибут           | Смысл                                   |
|--------------------|-------------------------------------------|
| `data-direction`  | `up` \| `down` \| `both` (по умолчанию `both`) |

## Поддерживаемые SVG-теги геометрии

`rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `path`
(полный синтаксис `M/L/H/V/Z/C/S/Q/T/A`, включая относительные команды,
через Apache Batik). Кривые преобразуются в ломаную с допуском 0.1 единицы
SVG. Поддержаны вложенные атрибуты `transform` на элементах и группах.
Площадь по умолчанию по-прежнему считается по габаритам, а не по точному
контуру; для непрямоугольных помещений задавайте `data-area` явно.

## Валидация и сценарий расчёта

`data-id` уникален среди всех элементов плана; `OUTSIDE`, `@` и запятая
зарезервированы. Вместимость обязательна и должна быть целым числом от нуля.
Масштаб, площадь, ширина и пропускная способность — конечные числа больше
нуля. `data-connects` содержит ровно два разных идентификатора; обычные
двери и выходы проверяются на существование узлов. Только выход может
ссылаться на `OUTSIDE`. Для лестницы проверяются этажи, направление и
существование узла на текущем этаже.

Без `data-scale` и `data-floor` используются значения 1 и 1. Этаж — целое
число. Неверные явно указанные числа отвергаются. DTD и внешние XML-сущности
запрещены. Вложенные `<svg>` с собственным viewport, CSS `transform` и
элементы модели внутри `defs`/`symbol`/`clipPath`/`mask` не поддержаны и
отвергаются; используйте обычные группы с SVG `transform`.

Актуальный расчёт работает с одним этажом. Фактическая загрузка задаётся
отдельно через `occupancy` в интерфейсе/API; вместимость не означает, что
помещение заполнено. `data-throughput` — готовое значение в чел/с,
**ширина повторно на него не умножается**. Ширина и площадь пока не меняют
скорость людей автоматически. Заблокированные проходы задаются отдельным
списком `blockedConnections`, исходный SVG изменять не нужно.

Лестницы парсятся, но исключаются из событийного расчёта с предупреждением.
Исходный консольный `EvacGraphBuilder` всё ещё сворачивает этажные суффиксы;
его вывод не является расчётом движения между этажами.

## Идеи на будущее (не реализовано)

- Многоэтажная сборка `Building` из нескольких SVG-файлов (по одному на этаж)
  с автоматическим связыванием лестниц через `@floor`.
- Направленность рёбер (сейчас граф неориентированный).
- Расчёт `data-throughput` по нормативной формуле из ширины проёма вместо
  ручного задания.
